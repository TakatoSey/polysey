# Живая торговля: постановка на VPS Ubuntu

Этот документ — про режим `TRADING_MODE=live`, в котором бот **подписывает и
отправляет реальные ордера** на Polymarket CLOB своим ключом. Paper-режим
остаётся как был: он по-прежнему нужен, чтобы понять, за кем стоит идти.

Прочитай раздел «Чего я не проверял» до того, как включишь live.

---

## 0. Как это устроено

Логика копирования одна на оба режима: обнаружение сделок лидера, серии,
размер, диапазон цены, slippage, минимум рынка, стопы, выходы. Отличается
только исполнение и источник денег.

| | paper | live |
|---|---|---|
| Fill | имитируется по снимку стакана | реальный FAK-ордер, fill сообщает биржа |
| Баланс | свой счётчик в базе | **USDC с биржи** (`/balance-allowance`) |
| Позиции | из своих сделок | **из Polymarket** (`/positions`), плюс своя атрибуция по лидерам |
| Комиссия | расписание рынка либо оценка | из трейдов ордера |
| Выплата | бот начисляет | приходит редимом на Polymarket, бот её не выдумывает |

Точный порядок в live: сигнал → проверки цены и лимитов на том же снимке
стакана, что и в paper → если paper-режим сказал бы «пропуск», ордер вообще не
подписывается → иначе подписывается market-FAK с ценовым лимитом
(`цена лидера ± slippage`, но не за пределами диапазона) → POST → если ответ не
сказал, сколько исполнилось, бот **спрашивает биржу**, а не додумывает.

Деньги: биржа — источник истины. Баланс и позиции читаются в фоне
(`LIVE_STATE_REFRESH_SECONDS`, по умолчанию 5 с), свои филлы проецируются на
последнее чтение, следующее чтение проекцию заменяет. Наш учёт хранит атрибуцию
по лидерам и идемпотентность; расхождение с биржей больше
`LIVE_DRIFT_TOLERANCE_USDC` **останавливает новые покупки** и пишет в чат.
Продажи, стопы и выплаты не блокируются никогда.

Скорость: на пути ордера нет ни одного лишнего запроса. Пока движок ждёт
метаданные рынка, параллельно прогреваются tick size, neg-risk и ставка
комиссии этого токена — то, что клиент иначе дозапрашивал бы уже в момент
подписи. Баланс на горячем пути не запрашивается: он читается фоном. Лимит
цены считается локально. Итог — один POST на ордер; его длительность видна в
логе как `submit_ms`.

## 1. Что нужно на стороне Polymarket

1. **Аккаунт с деньгами.** USDC на Polygon в том кошельке, которым будешь
   торговать. У аккаунта Polymarket, созданного по email, деньги лежат на
   **proxy-кошельке** — его адрес виден в интерфейсе (Deposit / профиль).
2. **Разрешения (allowance).** Биржа должна иметь право двигать твой USDC.
   Самый простой способ: **сделай одну сделку руками в интерфейсе Polymarket
   этим же кошельком** — разрешения выставятся сами. Проверить можно шагом 4:
   в отчёте `exchange_allowance` должен быть больше нуля.
3. **Приватный ключ, которым подписываются ордера.**
   - аккаунт по email (Magic): в интерфейсе Polymarket есть экспорт ключа
     (Settings → Export private key). Это ключ **подписи**, деньги остаются на
     proxy-кошельке → `POLYMARKET_SIGNATURE_TYPE=1`,
     `POLYMARKET_FUNDER=<адрес proxy>`;
   - аккаунт, созданный из браузерного кошелька: ключ этого кошелька,
     `POLYMARKET_SIGNATURE_TYPE=2`, `POLYMARKET_FUNDER=<адрес proxy>`;
   - обычный EOA, который сам держит USDC: `POLYMARKET_SIGNATURE_TYPE=0`,
     `POLYMARKET_FUNDER` можно не задавать.

   Неверный `SIGNATURE_TYPE` или `FUNDER` = ордера будут отклоняться или уйдут
   не с того кошелька. Шаг 4 это проверяет до первого ордера.

**Про ключ.** Он даёт полный контроль над кошельком. Держи на торговом
кошельке только ту сумму, которой готов рисковать; основные средства — в
другом месте. Ключ не хранится в git, не пересылается в чат и не попадает в
бэкапы вместе с базой.

## 2. Отдельный экземпляр рядом с paper

Paper у тебя уже работает — его трогать не нужно. Live ставится **вторым
экземпляром**: своя папка, своя база, свой Telegram-бот. Так paper продолжает
собирать статистику по лидерам, а живой бот не делит с ним ни деньги, ни
учёт, ни ограничение «один процесс на базу».

```bash
# на VPS, рядом с существующей установкой (обычно ~/polycopy)
cd ~
git clone https://github.com/TakatoSey/polysey.git polylive
cd polylive
cp .env.example .env
```

Новый бот в Telegram: @BotFather → `/newbot` → токен. Свой токен для live —
это ещё и способ не путать сообщения paper и live в одном чате.

`.env` для live (остальное можно оставить как в paper):

```dotenv
TELEGRAM_BOT_TOKEN=<токен нового бота>
TELEGRAM_ALLOWED_USER_ID=<твой numeric id, тот же>

# ВАЖНО: своя база, а не база paper-бота
DATABASE_URL=postgresql+asyncpg://polycopy:polycopy@db:5432/polycopy

TRADING_MODE=live
LIVE_CONFIRM=I_UNDERSTAND_REAL_MONEY
POLYMARKET_PRIVATE_KEY=0x....            # ключ подписи
POLYMARKET_FUNDER=0x....                 # кошелёк с USDC (proxy)
POLYMARKET_SIGNATURE_TYPE=1              # 0 EOA / 1 email-proxy / 2 browser-proxy
POLYGON_CHAIN_ID=137

# на старте — маленькие и осторожные
LIVE_DRY_RUN=true
LIVE_MAX_ORDER_USDC=2
LIVE_MAX_DAILY_LOSS_USDC=5
LIVE_DRIFT_TOLERANCE_USDC=1
LIVE_STATE_REFRESH_SECONDS=5

# лимиты копирования на первое время
COPY_BALANCE_PCT=0.02
MAX_OUTCOME_EXPOSURE=5
MAX_TRADE_SIZE=2
MIN_CASH_RESERVE_PCT=0.30
```

Изоляция контейнеров и томов — отдельным именем проекта:

```bash
cd ~/polylive
docker compose -p polylive up -d --build
```

`-p polylive` даёт свои контейнеры (`polylive-bot-1`, `polylive-db-1`) и свой
том Postgres. Проверь, что paper остался на месте: `docker compose -p polycopy ps`
(или `docker ps` — там должны быть контейнеры обоих проектов).

Права на `.env`: `chmod 600 .env`. В нём приватный ключ.

## 3. Порядок включения (не пропускай шаги)

### Шаг 1. Сборка и preflight (ордеров не отправляет)

```bash
cd ~/polylive
docker compose -p polylive up -d --build
docker compose -p polylive exec -T bot python -m app.live_check
```

Отчёт — JSON. Смотри:

- `signer` — адрес ключа подписи;
- `funder` — кошелёк с деньгами (должен совпадать с адресом в интерфейсе
  Polymarket);
- `usdc_balance` — сколько USDC видит биржа;
- `exchange_allowance` — разрешение биржи на этот USDC, должно быть > 0;
- `collateral_contract` / `exchange_contract` — адреса, которые называет сама
  биржа (не из чьей-то памяти);
- `ready_for_live: true` и пустой `blocking_problems`.

Если `exchange_allowance: "0"` — сделай одну сделку руками в интерфейсе
Polymarket этим кошельком и повтори проверку.

Можно проверить и конкретный рынок (tick size, neg-risk, комиссия, наши
shares):

```bash
docker compose -p polylive exec -T bot python -m app.live_check <TOKEN_ID>
```

### Шаг 2. Dry-run на живых сигналах

`LIVE_DRY_RUN=true` уже стоит. Добавь одного лидера, дай боту поработать.
Он будет проходить весь путь, подписывать ордер и **не отправлять** его:

```bash
docker compose -p polylive logs -f bot | grep -E 'live_dry_run_order|copy_sizing|copy_rejected'
```

Убедись, что размеры и цены выглядят так, как ты ожидаешь. В панели Telegram
заголовок должен быть `POLYSEY · 🔴 LIVE · dry-run`.

### Шаг 3. Первый реальный ордер на минимальной сумме

```bash
nano .env   # LIVE_DRY_RUN=false, LIVE_MAX_ORDER_USDC=2
docker compose -p polylive up -d --build bot
docker compose -p polylive logs -f bot | grep -E 'live_order_submitted|live_order_failed|copy_executed'
```

После первой покупки сверь три вещи:

1. в `live_order_submitted` есть `order_id`, `matched_shares` и `submit_ms`;
2. интерфейс Polymarket показывает эту позицию тем же объёмом;
3. `/status` в Telegram показывает тот же USDC, что и биржа, и нет
   предупреждения о расхождении.

Только после этого поднимай `LIVE_MAX_ORDER_USDC`, `MAX_TRADE_SIZE`,
`MAX_OUTCOME_EXPOSURE` и `COPY_BALANCE_PCT` — по одному значению за раз, с
пересборкой `docker compose -p polylive up -d --build bot`.

### Шаг 4. Ежедневный контроль

```bash
# что вообще происходит
docker compose -p polylive logs --since=30m bot | grep -E 'live_order|live_state|live_cash_drift|live_share_drift|live_daily_loss_stop'

# сверка учёта с историей (сеть не нужна)
docker compose -p polylive exec -T bot python -m app.ledger_audit
```

`live_cash_drift` / `live_share_drift` — учёт разошёлся с биржей; новые
покупки при этом уже остановлены и в чат пришло сообщение. Причина обычно
внешняя: сделка руками в интерфейсе, редим выигрыша, перевод денег. После
расхождения имеет смысл сверить позиции глазами и, если наш учёт врёт,
пересобрать его — проще всего `/reset` (стирает торговую историю live-бота,
но не трогает деньги на бирже) и дать боту заново набрать позиции.

## 4. Что где лежит и что чем управляется

| Где | Что |
|---|---|
| `~/polycopy/.env` | paper-бот, `TRADING_MODE=paper`, свой токен |
| `~/polylive/.env` | live-бот, ключ, funder, лимиты |
| `docker compose -p polylive ...` | все команды live-экземпляра |
| Telegram → «⚙️ Настройки» | лимиты режима, тумблер уведомлений, «⛔ Стоп торговли» |
| `/kill` | снять свои ордера с биржи и поставить копирование на паузу |
| `/pause` · `/resume` | пауза без снятия ордеров |
| `python -m app.live_check` | preflight, только чтение |
| `python -m app.ledger_audit` | сверка учёта, только чтение |

Ограничители, которые действуют в live (все — до отправки ордера):

- `LIVE_MAX_ORDER_USDC` — жёсткий потолок одного ордера;
- `LIVE_MAX_DAILY_LOSS_USDC` — реализованный убыток за UTC-сутки, после
  которого новые покупки останавливаются до следующих суток;
- `LIVE_DRIFT_TOLERANCE_USDC` — расхождение с биржей, после которого новые
  покупки останавливаются;
- плюс всё, что было в paper: диапазон цены лидера, slippage, лимит на исход,
  резерв кэша, минимум рынка, максимум серии.

Выходы, стопы и выплаты не останавливаются ни одним из этих лимитов —
отказать в сокращении реальной позиции хуже, чем действовать по слегка
устаревшему числу.

## 5. Откат

```bash
cd ~/polylive
docker compose -p polylive exec -T bot python -c "pass"   # проверка, что контейнер жив
# 1. остановить торговлю мягко: /kill в Telegram (снимет ордера и поставит паузу)
# 2. остановить контейнер
docker compose -p polylive stop bot
```

Остановка контейнера **не закрывает открытые позиции** — они остаются на
Polymarket, закрывать их нужно самому (в интерфейсе) или снова запустив бота.
Если нужно вернуться к наблюдению без денег: `TRADING_MODE=paper` в
`~/polylive/.env` и пересборка. База при этом остаётся, но её баланс перестанет
означать биржевой USDC — для чистого paper-теста лучше `/reset`.

## 6. Чего я не проверял

Честно про границы этой работы:

- **Живой биржи в моём окружении нет.** Код написан по исходникам официального
  `py-clob-client` 0.34.6 (подпись, L2-авторизация, market-FAK, balance-allowance)
  и покрыт тестами против подставной биржи: 39 тестов на то, что отправляется,
  что записывается и, главное, что **не** записывается, когда биржа ответила
  непонятно. Но ни один реальный ордер этим кодом ещё не проходил. Первый
  ордер на $1–2 из шага 3 — это и есть настоящая проверка.
- **Разрешения и редим** — операции в блокчейне; бот их не делает. Выигрыш
  приходит на кошелёк после редима на Polymarket, и бот его не начисляет сам
  (иначе он бы придумал деньги). В учёте выплата отмечается, кэш берётся из
  следующего чтения биржи.
- **Формат ответа на POST /order** может отличаться полями. Поэтому ответ
  разбирается защитно: если в нём не сказано, сколько исполнилось, бот
  спрашивает `/data/order/{id}` и трейды; если и там неясно — фил **не
  записывается**, а сверка с биржей это покажет и остановит покупки.
- **Частичные филлы и цена**: FAK берёт, что есть, остальное отменяет. Средняя
  цена берётся из трейдов ордера; если трейды недоступны, используется цена
  ордера, и это пишется в лог предупреждением.
- **Правила и доступность Polymarket** в твоей юрисдикции — на твоей стороне.
- Прохождение тестов не означает прибыльность. Копирование сильного трейдера
  на своих деньгах остаётся риском потери всей суммы.
